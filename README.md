## ✨ Features

### 🗂️ Prayer Management
- Add personal prayer requests with title, description, and categories
- Pray **for others** — attach a person's name and phone number
- Track **updates** over time and add **prayer points** with Bible verses
- Mark prayers as **answered** and record a **testimony** — kept as a running list across resume / re-answer
- An **Answered prayers** reflection view celebrating God's faithfulness

### 🤝 Community
- Create or join **prayer groups** by invite code, link, or QR
- **Friends** & friend requests — add people by tapping suggestions from your shared groups, by email, or via a shareable **friend link / QR**; invite friends to your groups
- Share a personal prayer to one or more groups (optionally **anonymously**)
- **Two-way sync** — updates, prayer points, verses, categories, and answered status stay in sync between your prayer and its shared copies
- React with **"I'm praying"**, post **member updates** and **testimonies**
- **Save** a community request into your own list; opt-in **auto-add** per group
- **"See translation"** — translate any group prayer into your language on demand
- **New-since-last-visit** badges per group; admin tools to manage members/invitations

### 🤖 AI-Powered Features
- **Prayer points** — Claude AI suggests prayer angles with Bible verses per point (or add them manually)
- **Daily Bible verse** — one shared verse per day per language, generated by a server-side Edge Function
- **Read verses in the app** — tap any reference (the daily verse, a prayer point, a prayer session passage, or a Scripture suggestion) to open it in an in-app reader, pull the fuller passage on demand, and keep a "read the whole chapter" link to Bible.com for the deepest dive
- Verse text is sourced from the **YouVersion Platform API** (authoritative publisher text) when configured (`VITE_YOUVERSION_ENABLED` + `YVP_APP_KEY`), and otherwise falls back to the guardrailed AI text path — both go through a server-side proxy that keeps the App Key out of the bundle
- All AI suggestions are generated in the user's language
- **A humble assistant, by design** — every AI call carries a theological guardrail (never speaks for God, never poses as pastor or prophet, always points back to reading Scripture in context). That posture is surfaced in the UI too: a consistent disclaimer wherever suggestions appear, an "AI assistance" panel in Settings to review it, and a one-tap way to turn AI suggestions off
- AI calls **always** go through a server-side proxy that holds the key — it is never bundled into the browser, in dev or prod. The proxy requires a valid session, pins the model, and enforces per-user rate limits + payload caps

### 📅 Weekly Prayer Plan
- Create categories (Family, Health, Church, Work…) with custom emoji and color
- Day-centric editor: tap a day to choose what you pray, with today highlighted and prayer counts
- Per-prayer day overrides, category reordering, and smart "schedule automatically" for empty days

### 🕊️ Faithfulness & Reflection
- **Weekly recap** (answered prayers / testimonies) on the home screen — a remembrance of God's faithfulness
- First-run **onboarding** to orient new users
- **Export my data** — download your full prayer journal as JSON

### 🌍 16 Languages
Full UI support for:
**French, English, German, Portuguese, Chinese, Spanish, Hindi, Japanese, Swahili, Amharic, Indonesian, Tagalog, Korean, Russian, Arabic, Persian**

Every label, tooltip, button, and daily verse adapts to the selected language. Each language ships as its own lazy-loaded chunk. Dynamic prayer content is translated via Claude AI and cached in Supabase.

### 📱 PWA & Offline
- Installable on Android, iOS, and desktop
- **Works offline** — create, edit, delete, answer prayers and add updates/points/verses while disconnected
- Optimistic UI with a durable **IndexedDB write queue** that replays on reconnect (idempotent, with a visible "syncing" indicator)
- Local snapshot hydration so your journal loads instantly, even offline

### 🔔 Push Notifications
- Real **Web Push** daily reminders — delivered even when the app is closed, listing that day's prayer subjects by title
- Follow-up reminders at a user-chosen frequency (every 3 days, weekly, every 2 weeks, monthly) — nudges you to reach out to whoever each active prayer is for (yourself included) and add what you learn back to the prayer
- Server-driven: both reminders are sent by one `pg_cron`-invoked Supabase Edge Function, independently toggled per device
- _iOS: push requires the app installed to the Home Screen (PWA), iOS 16.4+_

### ♿ Accessibility
- Every modal supports **Esc-to-close**, **focus trapping**, and `role="dialog"` semantics
- Icon-only buttons carry accessible names

### 🌙 Light & Dark Mode
- Toggle between light and dark themes, saved to `localStorage` and applied instantly

### 🔒 Private & Secure
- Auth via Google OAuth or Email/Password (Supabase Auth)
- All data stored in your own Supabase database with **Row Level Security**
- Group joins validated server-side by invite code; shared-prayer writes scoped to their owner
- Secrets are **server-side only** — the Anthropic key and VAPID private key are never `VITE_`-prefixed, so they can't ship in the browser bundle
- Strict **Content-Security-Policy** (no `unsafe-inline`/`unsafe-eval` scripts), HSTS, and a locked-down `Permissions-Policy`
- AI relay is session-gated with **per-user rate limiting** and request validation
- See [`docs/THREAT_MODEL.md`](./docs/THREAT_MODEL.md) for the full threat model (DB breach, XSS, stolen device, compromised Supabase/AI provider, leaked recovery code, forgotten passphrase)

### 🔐 Prayer Vault — End-to-End Encryption
- Opt-in **client-side E2EE** for your private prayers — encrypted with a passphrase only you know (we never see it)
- **AES-256-GCM** content encryption via the Web Crypto API; the master key is wrapped by a key derived from your passphrase and never leaves the device in plaintext
- **Nested data is encrypted too** — prayer updates and prayer points (not just the title/description) are encrypted before they reach the server, so no sensitive content is stored in plaintext
- **One-time recovery code** generated at setup — the only way back in if you forget your passphrase (there is no other backdoor)
- **Auto-locks on inactivity**; unlock once to read/edit, lock instantly from Settings, or change your passphrase anytime
- Vault key state is held in **IndexedDB** (not `localStorage`); the wrapped key syncs across your devices
- **Sharing a prayer to a group publishes its plaintext** by design — encryption covers the private scope only

# Clone the repo

## ⚙️ Environment Variables

Create a `.env` file at the project root. Anything **`VITE_`-prefixed is exposed to the browser bundle** — never put a secret there. Secrets stay un-prefixed and are read only server-side.

```env
# Client (safe to ship in the bundle)
VITE_SUPABASE_URL=https://your-project.supabase.co/rest/v1/
VITE_SUPABASE_ANON_KEY=your-anon-key
VITE_VAPID_PUBLIC_KEY=your-vapid-public-key      # Web Push (npx web-push generate-vapid-keys)
VITE_DONATION_URL=https://paypal.me/your-handle  # optional
VITE_YOUVERSION_ENABLED=true                     # optional — source verse text from YouVersion

# Server-only — NOT VITE_ prefixed, never bundled
ANTHROPIC_API_KEY=your-claude-api-key            # AI features (no client fallback)
YVP_APP_KEY=your-youversion-app-key              # optional — in-app verse reader (platform.youversion.com)
```

> **The Anthropic key never reaches the browser** — there is no `VITE_` fallback. In dev, the Vite dev-server proxy injects it Node-side ([`vite.config.js`](./vite.config.js)); in prod, the [`api/anthropic.js`](./api/anthropic.js) serverless function does. Set `ANTHROPIC_API_KEY` in your Vercel project env.
>
> The **YouVersion App Key** follows the same rule: set `YVP_APP_KEY` (server-only) and `VITE_YOUVERSION_ENABLED=true` (public on/off flag) to read authoritative verse text in the app. The dev proxy and [`api/youversion.js`](./api/youversion.js) inject it as `X-YVP-App-Key` server-side. Leave both unset to keep the AI text fallback.
>
> The **VAPID private key** is used only by the `send-daily-reminder` and `send-follow-up-reminder` Edge Functions and lives in Supabase secrets (`supabase secrets set VAPID_PRIVATE_KEY=...`) — never in `.env` and never `VITE_`-prefixed.

## 🗄️ Database Setup

Run these SQL files in your Supabase SQL editor (in order):

1. [`supabase/community_schema.sql`](./supabase/community_schema.sql) — core + community tables, RLS, helper functions
2. [`supabase/migration.sql`](./supabase/migration.sql) — sharing, two-way sync, provenance, realtime
3. [`supabase/security_hardening.sql`](./supabase/security_hardening.sql) — invite-code-validated joins, forgeable-source fix
4. [`supabase/offline_client_ids.sql`](./supabase/offline_client_ids.sql) — client-id sync RPCs for offline writes
5. [`supabase/offline_conflict_hardening.sql`](./supabase/offline_conflict_hardening.sql) — `answer_prayer` (append-not-overwrite testimonies)
6. [`supabase/push_notifications.sql`](./supabase/push_notifications.sql) — `push_subscriptions` table + `pg_cron` job for `send-daily-reminder`
7. [`supabase/follow_up_reminders.sql`](./supabase/follow_up_reminders.sql) — adds the follow-up reminder columns to `push_subscriptions` + its own `pg_cron` job for `send-follow-up-reminder`
8. [`supabase/verse_cache.sql`](./supabase/verse_cache.sql) — shared, world-readable cache of resolved Scripture text (one fetch per verse for all users)
9. [`supabase/community_translation_cache.sql`](./supabase/community_translation_cache.sql) — group-scoped shared cache for community translations (members reuse each other's)
10. [`supabase/split_reminder_crons.sql`](./supabase/split_reminder_crons.sql) — **upgrade only**: run once if your project still has the old combined `send-reminders` cron, to cut over to the two split jobs above
11. [`supabase/user_settings.sql`](./supabase/user_settings.sql) — account-level `user_settings` table (language + reminder prefs synced across browsers/devices)

> The daily verse is served client-side from a curated pool of ~200 vetted,
> prayer-themed references ([`src/content/dailyVerses.js`](./src/content/dailyVerses.js)),
> rotated by day-of-year so everyone sees the same verse each day and the year
> rarely repeats. A hand-vetted core set ships embedded text in all 16 languages
> (instant + offline); the rest resolve their text once through the shared
> `verse_cache`/YouVersion pipeline and are cached forever after — zero recurring
> cost, and never AI-generated Scripture. The old AI-generated `daily_verse` table
> and its cron are no longer used and can be dropped.

## ☁️ Edge Functions

| Function | Purpose | Trigger |
|---|---|---|
| `send-daily-reminder` | Sends the localized daily Web Push (today's prayer subjects) at each user's local reminder time | `pg_cron`, every 15 min |
| `send-follow-up-reminder` | Sends the localized follow-up Web Push (reach out to who you prayed for) at each user's local reminder time, every `follow_up_days` | `pg_cron`, every 15 min |

Both functions share localization templates and scheduling logic from [`supabase/functions/_shared/reminders.ts`](./supabase/functions/_shared/reminders.ts) but run as separate deployments with separate cron jobs, so either reminder can be redeployed, rescheduled, or disabled without touching the other.

> `generate-daily-verse` is **deprecated** (the daily verse is now client-side). If
> it's still deployed, unschedule its cron and delete the function so it can't run
> up an AI bill:
> ```sql
> select cron.unschedule('generate-daily-verse');  -- only if such a job exists
> ```
> ```bash
> npx supabase functions delete generate-daily-verse
> ```

```bash
# Push reminders (generate a VAPID keypair first: npx web-push generate-vapid-keys)
npx supabase functions deploy send-daily-reminder --no-verify-jwt
npx supabase functions deploy send-follow-up-reminder --no-verify-jwt
npx supabase secrets set VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:you@example.com
```
